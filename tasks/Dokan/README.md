# 福利寮道馆

道馆任务固定只选择带“鑫”图标的福利寮，并在馆主阶段放弃突破。

## 流程

1. 按运行时间和星期设置进入道馆，清空历史次数记录，从首次进入的筛选页面底部读取游戏实际剩余次数；0次结束，1次挑战一馆，2次连续挑战两馆。
2. 建立道馆按钮为灰色时直接筛选；可点击时先确认建立成功。
3. 列表每0.3秒检查稳定状态，连续两次稳定后，同一帧批量检查“鑫”图标；仅打开符合图标的道馆读取人数。单次稳定确认最长3秒，超时后在原位置重试，仍不稳定则结束本次筛选，避免跳过未检查的页面。刷新次数超过设定值后，人数门槛减半；达到20次仍未找到则结束当日任务并按独立推送配置提醒。
4. 集结时设置馆员攻击优先级和御魂，连续两次挑战仅在第一把切换御魂。
5. 进行馆员战。馆主阶段直接放弃突破；误入馆主准备或战斗页面时退出。
6. 有第二次机会时选择“再战道馆”，确认返回庭院后随机等待60～65秒，再进入道馆继续第二次筛选；最后一次保留赏金。
7. 奖励页面识别后等待1秒截图。任务自动结束时识别蓝票数量，按日期汇总本次任务的所有截图并推送；发送成功后删除截图，关闭推送或发送失败时保留。

## 配置

保留运行时间、星期限制、馆员攻击优先级、御魂配置、最低防守人数、降低人数要求的刷新次数、结算截图开关和独立推送配置。馆员战斗固定自动连战，超时沿用全局战斗设置，不提供单独的成员战斗配置组。挑战次数由游戏画面识别，不提供手动次数设置；未识别成功时结束本次筛选。

独立渠道留空时沿用全局推送配置和开关；填写后不受全局开关影响。图片推送需使用 go-cqhttp。

## MuMu 原生后台滚轮筛选

在道馆的“福利寮道馆配置”中打开“MuMu 原生后台滚轮筛选”即可启用，默认关闭。配置字段是 `dokan_config.native_wheel_enable`，已有的旧滚轮开关会自动迁移到新字段。

每轮刷新依次检查当前屏，向下滚动9次后检查第二屏，再向下随机滚动5或6次后检查底部；三屏都未找到符合条件的道馆才刷新。再次刷新和再战道馆后重新执行9、5–6的顺序。到达底部的实际位置取决于游戏对滚轮的响应，不额外补滚。

第一段从第一条事件发出到最后一条发出，目标耗时0.75–1秒，8个随机间隔共同满足总时长。相邻事件间隔均随机0.05–0.15秒，间隔包含ADB发送耗时。第二段优先满足次数和随机间隔：5次滚动的4个间隔合计0.2–0.6秒，6次滚动的5个间隔合计0.25–0.75秒，不额外拉长到0.75–1秒。最后一条事件的发送及系统调度可能使实测时间稍长，日志记录实际耗时和输入后端。每段结束等待1.5秒，随后开始截图和原有的连续两次稳定检查，稳定后再筛选“鑫”图标和人数。稳定检查期间仍在滚动时会继续等待，不会使用旧截图选道馆。

滚动全部通过当前实例的ADB连接和MuMu内部原生鼠标设备执行，支持后台运行。日志中的 `backend=mumu_native` 表示使用该输入方式。前台窗口和宿主机鼠标由用户正常使用。

通过MuMu输入服务检测设备，按当前屏幕旋转转换坐标；每条滚轮事件都包含位置、`REL_WHEEL`和`SYN_REPORT`，减少宿主机鼠标移动对批次落点的影响。当前MuMu驱动的一格滚轮对应原生值100。MuMu需要已有的ADB root权限。每段开始前的设备检测和定位不计入滚轮数量或批次耗时。

无法识别MuMu原生鼠标、鼠标定位失败或输入中途失败时结束本次筛选，按现有道馆失败调度重试，不重发已经部分执行的9次/5–6次滚动。截图、点击、识别、人数条件和刷新上限仍由现有道馆流程处理。启用此功能需要MuMu和ADB连接。

## 福利寮插件触发

福利寮检测服务单独安装和维护，不包含在 OAS 仓库中。在检测服务中配置群号、指定成员和开启关键词；OAS 只查询接口返回的当天开启状态。

在道馆页面启用插件状态触发，填写完整接口地址（例如 `http://服务器IP:2537/welfare-dojo/today`）和插件配置中的 `api_token`。OAS 使用 `GET` 请求及 `Authorization: Bearer <api_token>` 请求头，接口只返回当天日期和 `opened` 布尔值。默认关闭；开启后必须确认今天开启福利寮才会进入道馆，原来固定运行时间到点也会等待确认。

默认仅在北京时间20:00至22:00查询，开始、结束时间可自行配置；开始时间包含在内，结束时间不再发起新查询。支持跨午夜时段，开始和结束相同表示全天查询。检测间隔默认60秒，可自行填写1至86400秒。每次查询完成后等待这个间隔；请求耗时、当前任务结束时间、脚本休息或停服等待也会影响实际启动时间。

检测服务按北京时间（UTC+8）核对消息时间，OAS 再次核对接口日期，只接受今天的 `opened: true`。昨天的开启状态在零点失效。群号、成员和关键词仅在检测服务中配置，OAS 不读取聊天正文。

尚未确认当天开启时，道馆仍保留在等待列表，显示下次允许查询插件的时间；保存参数不会将它从列表移除。这个时间表示状态检查时间，实际进入道馆仍需当天开启确认。需要手动测试道馆时先关闭插件状态触发，并将下次运行时间设为当前时间；插件触发开启时，手动调整时间也会继续等待确认。

确认开启后当天停止查询，重启也会读取已确认记录而停止查询。当天自动触发一次，该次任务内部仍按设置挑战两次；第二天进入查询时段后恢复检测。时段内确认成功的任务即使到22:00还未执行，仍等当前任务结束后优先执行。

确认后空闲时尽快运行道馆；其他任务进行中则等当前任务结束后优先执行。星期限制、每日次数、重启恢复和脚本休息设置继续生效。未确认时其他任务正常调度；接口失败按间隔重试，不因失败开启道馆或耗尽每日检查预算。

触发记录保存在 `config/dokan_qq_messages.db`，重启不会重复触发；只保存日期、配置摘要和状态，不保存消息正文或令牌。后台查询不保存截图；配置文件变化时重新读取，状态只在确认开启或消耗触发时写入。旧版 NapCat 接口配置需改为插件地址和插件令牌，旧的消息触发缓存不会直接沿用。
