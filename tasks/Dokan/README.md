# 福利寮道馆

道馆任务固定只选择带“鑫”图标的福利寮，并在馆主阶段放弃突破。

## 流程

1. 按运行时间和星期设置进入道馆，读取游戏实际剩余次数。
2. 建立道馆按钮为灰色时直接筛选；可点击时先确认建立成功。
3. 只检查“鑫”图标和最低防守人数。刷新次数超过设定值后，人数门槛减半；达到20次仍未找到则结束当日任务并按独立推送配置提醒。
4. 集结时设置馆员攻击优先级和御魂，连续两次挑战仅在第一把切换御魂。
5. 进行馆员战。馆主阶段直接放弃突破；误入馆主准备或战斗页面时退出。
6. 有第二次机会时选择“再战道馆”，最多等待120秒识别到筛选页面后继续；最后一次保留赏金。
7. 奖励页面识别后等待1秒截图。任务自动结束时识别蓝票数量，按日期汇总本次任务的所有截图并推送；发送成功后删除截图，关闭推送或发送失败时保留。

## 配置

保留运行时间、星期限制、馆员攻击优先级、馆员战斗和御魂配置、每日挑战次数、最低防守人数、降低人数要求的刷新次数、结算截图开关和独立推送配置。

独立渠道留空时沿用全局推送配置和开关；填写后不受全局开关影响。图片推送需使用 go-cqhttp。

## 指定成员的群消息触发

在道馆页面的“QQ福利寮消息检测”中启用消息触发，填写 NapCat **OneBot HTTP服务端**地址、访问令牌（未设置鉴权则留空）、群号、指定成员的QQ号、开启关键词和检测间隔。通过群聊历史接口读取普通聊天记录，筛选该成员发送的文字消息。默认关闭；开启后必须匹配消息才会进入道馆，原来固定运行时间到点也会等待匹配消息。

默认仅在北京时间20:00至22:00查询，开始、结束时间可自行配置；开始时间包含在内，结束时间不再发起新查询。支持跨午夜时段，开始和结束相同表示全天查询。检测间隔默认60秒，可自行填写1至86400秒。每次查询完成后等待这个间隔；请求耗时、当前任务结束时间、脚本休息或停服等待也会影响实际启动时间。使用 `/get_group_msg_history` 查询，默认每页100条、最多5页；读取范围可配置，忙碌的QQ群中超出范围的消息可能漏读。

按北京时间（UTC+8）核对每条消息的发送时间，只匹配指定群和成员今天发送的普通聊天文字，忽略昨天的消息、异常时间戳和未来消息。昨晚已匹配的缓存也在零点自动失效，无需等下一次查询。开启词和排除词均可用换行或 `|` 分隔；匹配成功前，包含排除词或较新的取消消息时不启动。请使用明确的道馆相关词，图片或转发内容不作为开启依据。

匹配成功后当天停止所有NapCat查询，重启也会读取已匹配记录而停止查询。当天自动触发一次，该次任务内部仍按设置挑战两次；第二天进入查询时段后恢复检测。时段内匹配成功的任务即使到22:00还未执行，仍等当前任务结束后优先执行。

匹配后空闲时尽快运行道馆；其他任务进行中则等当前任务结束后优先执行。星期限制、每日次数、重启恢复和脚本休息设置继续生效。未匹配时其他任务正常调度；接口失败按间隔重试，不因失败开启道馆或耗尽每日检查预算。

触发记录保存在 `config/dokan_qq_messages.db`，重启不会重复触发；只保存消息摘要和状态，不保存消息正文或令牌。后台查询使用内存中的连接，不保存截图；配置文件变化时重新读取，状态只在消息或触发状态变化时写入。

NapCat HTTP服务端配置参见[官方说明](https://napneko.github.io/config/basic)。
