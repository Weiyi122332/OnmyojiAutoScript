# 对弈竞猜策略

`config.py` 声明下注选项，`script_task.py` 负责页面操作和调度。新增策略时，将取数和决策放在独立模块中。

## 下注时间

北京时间每天 10:00–24:00，共 7 场，每场 2 小时。`before_end_frog` 控制每场结束前多久开始下注，大于 0 秒且不超过 2 小时；默认 15 分钟。

设置为 `00:10:00` 时，7 场计划时间依次为 **11:50、13:50、15:50、17:50、19:50、21:50、23:50**。首次启用、修改提前时间及点击重新计算下次运行时间都会按场次排期。首次运行或任务组提前调用也会等待下注窗口；已经进入窗口时允许补执行，本场已下注后排下一场，最后一场后排到次日第一场。

排期计算在 `frog_schedule.py`。重试通常延后 1 分钟，若跨出当前下注窗口，则排到下一场的下注时间。显式指定的运行时间、cron 和随机浮动设置保留；实际下注仍需处于场次的下注窗口。调度器串行执行任务，其他任务占用设备时可能晚于计划时间启动。

## RSS 跟押（面灵气喵）

配置值为 `frog_rss`。参考 [assttyys_autojs 的对弈竞猜实现](https://github.com/zzliux/assttyys_autojs/blob/57350f30ccf205c62e308a1916772c07919c2743/src/common/funcList/401_%E5%AF%B9%E5%BC%88%E7%AB%9E%E7%8C%9C.ts)，从其 RSSHub 服务读取面灵气喵的大神动态：

`https://rsshub.zzliux.cn/163/ds/462382f1127b46c5add1185d88f0ea40`

1. 排除含“体验服”的动态，仅查看剩余最新 5 条。
2. 以北京时间计算当前两小时场次，例如 19:45 对应 18:00。动态必须发表于当天，且不能来自未来。
3. 在“对弈竞猜”内容中匹配该场时间和随后第一个“左、右、红、蓝、翻盘”建议，不跨到其他时间或上一局结果。
4. 左／红押左，右／蓝押右；翻盘按最新 OCR 人数押少数方，相同人数押右。翻盘人数无效或全为零时暂不下注。
5. 请求超时、RSS 无法解析或没有本场建议时，改用下述人数多数兜底。场次或阵容变化、下注窗口关闭时，返回庭院并安排 1 分钟后重试。若任务设置了 cron 或随机浮动，仍遵循调度器设置。

取数和解析代码在 `frog_rss.py`。发布日校验和下注前检查是 OAS 增加的保护措施。此选项固定跟押面灵气喵；参考脚本的匹配规则只验证了该博主。建议依赖博主发帖和外部 RSS 服务，不保证胜率。

## 人数多数兜底

RSS、大神、OAS 等首选策略获取不到本场有效押注信息时，重新读取游戏里的双方人数，押人数较多方；相同人数押右，与现有多数策略一致。暂未接入的哔哩哔哩选项也使用此兜底。大神有有效建议但票数相同时，保留其原有少数方规则。OAS 已保存的本场决策继续复用；新建兜底决策仍记录到历史中，可正常结算。

人数无效、全为零、场次或阵容变化、下注窗口关闭时暂不下注，安排 1 分钟后重试。多数方兜底不跳过游戏页面检查。

## 每次运行结果推送

每次执行 `run()` 结束时发送一次摘要，覆盖下注成功、本场已下注、休息中、暂缓下注和异常退出。内容包含场次、首选策略、下注方向与金额、双方人数、上局结算、建议来源或兜底原因，以及下次运行时间。只有游戏出现已下注标记后才报告“下注成功”。

检测到“已下注”时，立即将该帧完整 RGB 画面保存为内存中的 PNG。go-cqhttp 在同一条消息里发送文字和截图；本场原本已下注时也附带当前已下注画面。休息、等待下注时间、未完成下注和进页失败时仅推送文字。截图只属于本次运行，不读取前一次运行的图片。图文发送失败时降级为文字摘要；其他推送渠道暂只支持文字。

复用实例的全局推送开关和渠道配置；未开启全局推送时不发送。推送失败只记录日志，不影响竞猜结果或任务异常处理。摘要结构在 `frog_bet.py`。
