# 资源识别

从庭院底栏进入纳物库，通过后台 ADB 截图和 OCR 读取四项资源：金币、体力、勾玉、普通蓝票。不会统计限时蓝票。金币允许保留游戏显示的万/亿缩写，体力点击数字后读取浮层中的完整「已拥有」数量。

所有点击在文字或图片的安全区域内随机取点。体力匹配左侧图标后在图标内部点击，图标区域与右侧加号隔离；浮层的数量按「体力」标题的位置动态定位。普通蓝票必须选中「资源→基础」分类，并核对物品名称恰好是「神秘的符咒」后读取「持有」数量；不会点使用、购买或兑换按钮。完成后返回庭院。

任务默认开启，定时表达式为 `0 23 * * *`，即每天23:00（当前部署系统时区为北京时间）。脚本实例需要保持运行；已有任务不会被中途打断，到点后在当前任务结束后执行资源采集。可在任务页修改开关和定时规则，也可提前运行一次。

数据按实例保存在 `log/resource_inventory/<实例名>/`：

- `latest.json`：最近一次采集，包含四项数量、显示文本、是否精确、识别状态和时间。
- `days/YYYY-MM-DD.json`：该日最近一次成功快照，日期按北京时间计算。后续部分识别失败不会覆盖当天已有的完整快照。
- `history.jsonl`：每次采集记录。
- `evidence/YYYY-MM-DD/<采集编号>/`：对应采集的截图证据。

每日快照长期保留，现有日志的七天清理不删除此目录。读取失败用 `null` 和错误信息表示，不能当作零；金币的缩写数量会保留 `exact: false`。

OASX 右侧「资源」页通过 `GET /resources/<实例名>` 获取最近数据和可选日期；通过 `GET /resources/<实例名>?date=YYYY-MM-DD` 读取历史快照。刷新界面只读取已保存数据，不会同时操控模拟器。

也可以从仓库根目录运行一次独立识别（先将模拟器停在庭院，保持 OCR RPC 服务已启动）：

```powershell
python -m tasks.ResourceInventory --serial 127.0.0.1:16384 --adb <adb.exe路径> --config-name <实例名>
```

支持横屏16:9画面，会归一化到1280×720识别并按原分辨率换算点击。`res/` 的模板由实际纳物库界面裁出，用于确认基础分类选中状态、体力图标和普通蓝票图标；无需重新生成其他任务的资源。
