- 阵容保存为 `strategy/lineup_strategy.json`；编辑器与任务共享校验和加载逻辑，每局开始时重新读取配置，局内保持阵容快照。已移除的流火、冥府、大江山、狐妖及旧拼音值继续回退七角山。
- 开局处理六道场地必选页；`sixrealms_selection_enabled` 默认开启，关闭时只等待页面结束并继续截图，不主动选择。
- 通过勾玉、金币、纹章标志定位卡牌，再读取头像及羁绊；同一截图复用识别结果。
- 商店点击区域取自实际定位后的 Frame 第六个相对区域；同一购买流程累计最多点击三次。点击前确认该卡金币标志存在，点击后以同一位置金币标志消失确认成功；身份识别丢失不算成功。失败时若手牌还有空位，不出售手牌。
- 购买前通过定位标志统计手牌容量，不依赖身份 OCR；上卡既支持手牌数量减少确认，也支持连续两帧星级提升确认。
- 下阵前检查手牌空位，满手牌时先清理非阵容卡并装备御魂；仍无法腾位或已离开备阶段时暂缓下阵，避免连续拖拽失败。
- 系统卡每次下阵前及拖拽确认期间持续检查备阶段；进入战斗后立即停止，不将阶段切换误判为下阵成功，也不继续上阵先前选中的手牌。
- 回合、备/战/鬼/待与倒计时由普通、野怪、百鬼三套详情 Frame 读取，同一截图复用结果。升级/刷新保留 12 秒保护，棋盘动作在最后 2 秒停止。
- 首次百鬼确认本人昵称后，每回合首个关店画面读取本人生命。普通经济保留 50 金币，生命低于 60 时保留 40；低于 20 时停止升级、放开刷新额度。未达最终阶数时每回合刷新上限为 `max(0, 阶数 - 5)`，实际点击即计入额度。
- 售卖统一复核阶段、回合和连续两帧手牌数量减少；每个目标每回合失败两次后暂缓，仍允许处理其他目标和经济。满手牌时先处理可装配御魂、非阵容卡及无法装配的御魂，再考虑阵容卡。
- 棋盘通过表情按钮锚点读取普通、首领两套 Frame；前排为 1–6 号，后排为 7–12 号。仅在备阶段且商店关闭后读取，无法识别时返回未知并保留上阵记录；不据此判定空位或确认下阵成功，每次重拖前再次检查容量。
- 保留主要、次要羁绊纹章及装备槽预留；二荒川的金鱼按系统站位 12、6、11、5 检查详情确认。移动后在目标位置强制复核，确认成功才更新站位和交换记录；已确认非金鱼的位置在当局跳过。
- 百鬼投掷按本人黄色昵称框、锁消失及延时判断时机，投掷前重新截图，优先选择阵容所需御魂；所有玩家解锁后可选择其他目标。
- `hyakki_draft_enabled` 现在表示“百鬼优先所需御魂”：开启时优先阵容需求，关闭时仍参加投掷并随机选择已识别目标。
- 支持黄金复制术和特殊回合标志，并保留符咒复核、保段位、局数/时长限制及满币结束逻辑。
- 棋局独立补齐浮窗红叉、退出确认、奖励、庭院、协作和网络异常识别。处理弹窗后重新截图，连接失败时执行有界重连并恢复任务入口。
- 棋局截图流程会关闭意外打开的式神详情页；主动读取金鱼详情时显式豁免，结束或异常后恢复自动关闭。

## 阵容编辑器

在 OAS Web 服务地址后追加 `/tool/chesslineup` 可打开“百鬼阵容工坊”。支持拖放式神、御魂和纹章，调整站位、权重与羁绊，导入导出、保存和应用到脚本配置。编辑器静态文件位于 `module/server/web/chesslineup`，接口位于 `module/server/chesslineup_router.py`。

自定义阵容保存到本机 `strategy/custom_lineups.json`，不进入 Git；同步保留该文件及迁移备份。已有对局使用原阵容快照，新选择在下一局或重新启动棋局时生效。

## 当前框架适配

- `module/atom/frame.py` 与 `BaseTask.runframe()` 提供相对区域读取；Frame 额外参数纳入当前图像缓存键。
- 图像服务支持多个定位标志、灰度及掩码匹配，继续使用当前项目的截图缓存和 RPC 失效回退。
- Frame 同时支持 `Single` 文本和 `Digit` 数字 OCR；数字要求使用整数或整数列表，布尔值和字符串不会冒充数字条件。
- 原有有界点击兼容继续保留；购买改用棋局自己的三次累计上限和金币标志复核，公共 `BaseTask` 本次没有修改。
- 规则标注工具已补齐 Frame 的界面、配置模型、保存/重载、裁剪及只读预览；Digit 模式与运行时配套，其他规则的默认 profile 保持本项目的 `Default`。
- 拖拽支持快速/重试两种节奏；minitouch 批量发送完整手势，uiautomator2/scrcpy 不自动重放不确定的手势，异常时尽力松手。scrcpy 控制锁使用 `RLock`，允许同一手势与控制发送器嵌套加锁。
- 满币后的周目标调度调用当前项目的 `set_next_run_next_monday()`，继续遵循本项目的 cron 调度约定。
- 全局导航识别六道必选页和棋局结算标志；普通奖励页仍由公共奖励页面推进，避免误归到棋局。
- `runtime/shared_ui.py` 只在棋局及本次棋局重连服务中使用 16 项公共模板副本；优先使用来源模板，再尝试当前模板。识别、点击和批量缓存使用同一套规则，保留已匹配坐标。新版协作接受、拒绝、忽略三个按钮及庭院卷轴识别均已配套接入。
- 浮窗红叉使用棋局自己的规则，避免与 `GeneralBuffAssets.I_CLOSE_RED` 冲突；公共 `GameUi`、奖励页、邀请处理和调度器代码保持现有实现。
- 棋局町中入口失败且仍停留町中时，先经庭院重新进入，再交给导航器重试；仅在棋局及其重连服务中启用。
- 网络异常遵守当前实例的 `wait_10s`/`restart` 策略，也能读取来源的 `wait_5s` 值；连接失败最多尝试一次 30 秒重连，失败或再次断线交给既有异常重启机制。重连后重新执行启动恢复并清理旧回合、投掷及页面命中状态。
- `runtime/activity_watchdog.py` 只在棋局运行期间启用；连续 300 秒没有截图、识别或输入活动时触发现有 `GameStuckError` 恢复流程，退出棋局时恢复原线程的 profile 回调。
